# FusionEdge: lightweight infrared–visible image fusion, measured honestly

FusionEdge fuses an infrared (IR) image and a visible (RGB) image of the same scene into one RGB image. The goal is to keep what each sensor sees: people and engines that are hot in IR but dark or hidden at night, plus the colour and texture only the visible camera has. The model is small enough to target edge GPUs.

The project is built around a **fixed, pre-registered evaluation protocol** ([docs/PROTOCOL.md](docs/PROTOCOL.md)). Every change to a model, metric or acceptance rule is written down *before* the run it governs, and failed runs are kept with their explanations. The headline result is a negative one. Over three seeds, under a decision rule fixed before those runs, FusionEdge's backbone is **not supported** as an improvement over a plain CNN with the same output head. It is better on visible-similarity metrics and worse on infrared-similarity ones, and it runs 2.8× slower ([docs/RESULTS.md](docs/RESULTS.md)).

## Recommended model

**Use `baseline_simplecnn_inject`: the plain baseline backbone with the inject head** (`configs/baseline_inject.yaml`, checkpoint `experiments/baseline_simplecnn_inject/checkpoints/last.pt`).
- **Cost:** 13,089 parameters and 16.9 ms per 480×640 frame.
- **Stability:** steady across three seeds.
- **Behaviour:** never darkens and keeps the visible image's colour.

**FusionEdge is kept as a documented negative result.** Its dual-branch backbone, cross-modal attention and edge-guided gate cost 1.7× the parameters and 2.8× the latency. Over three seeds they buy visible-similarity at the expense of infrared-similarity, with several times more seed-to-seed variance. Despite the project name, FusionEdge is **not** the model to deploy. Baseline v6 is the reference without the inject head.

## Results at a glance (seed 1234, MSRS holdout, 108 images)

| | baseline v6 | baseline + inject | FusionEdge |
|---|---|---|---|
| parameters | 13,089 | 13,089 | 22,339 |
| latency, 480×640, RTX 4070 Laptop (median) | 16.7 ms | 16.9 ms | 47.0 ms |
| MI | 3.676 | **6.275** | 6.180 |
| SSIM_vi / MS-SSIM_vi | 0.902 / 0.927 | 0.906 / 0.925 | **0.914 / 0.932** |
| SSIM_ir / MS-SSIM_ir | **0.514 / 0.500** | 0.493 / 0.486 | 0.484 / 0.475 |
| pixels darkened / brightening outside IR-brighter areas | 23.7% / 27% | 0% / 4% | 0% / 4% |
| audit / acceptance gate | 17/17, 14/14 | 17/17, 14/14 | 17/17, 14/14 |

Full tables are in [docs/RESULTS.md](docs/RESULTS.md), generated from the run artifacts by `scripts/make_results.py`: all 8 metrics, the test split, the reference rows and the seed repeats. In short:

- **The inject head matters most.** It makes a model brighten only where IR is brighter, keep colour exactly, and never darken.
- **The backbone doesn't clearly help.** Over seeds 1234, 1235 and 1236, FusionEdge is clearly better on 3 of 8 holdout metrics (SF, SSIM_vi, MS-SSIM_vi) and the plain backbone with the same head on 3 (MI, SSIM_ir, MS-SSIM_ir); EN and AG show no clear difference. The pre-registered verdict is therefore "not supported", narrowly: the threshold is 5 of 8 and the result is exactly 5. FusionEdge also varies several times more across seeds.
- **Baseline v6 has the best IR-structure scores,** but it darkens and brightens well outside thermal targets.

## Method

All models fuse **luminance only**. The output's colour (Cb/Cr) is copied from the visible image, so no model can invent colour. The final models share one output head ([docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)):

```
g   = sigmoid(head(features))           per-pixel gate, head zero-initialised (g = 0.5 at start)
Y   = Y_vi + g * relu(IR - Y_vi)        add part of the IR excess, only where IR is brighter
out = recolour(Y, vi)                   fused Y + visible chroma
```

- **FusionEdge** (22,339 params): a shared stem and paired separable residual blocks for both modalities. These feed per-branch squeeze-excite, cross-modal attention on an 8×8 token grid, and a Sobel-edge-guided per-pixel modality gate, then the detail blocks and the head.
- **Baseline** (13,089 params): concatenate IR and visible, then a stem, 4 separable residual blocks and the head. v6 uses a sigmoid Y head; "baseline + inject" uses the head above.

The training loss is unsupervised, because MSRS has no fused ground truth. It combines L1 intensity to max(IR, visible), L1 gradient to the max of the source gradients, an SSIM term against both sources, an edge-retention term and a chroma term, with weights 8 / 10 / 2 / 1 / 1. Training uses Adam at 1e-4 with a cosine schedule to 1e-6, 60 epochs, batch 8, 128×128 random crops and flips, bf16 autocast, the loss computed in fp32, seed 1234, and deterministic kernels.

## Dataset

**MSRS** ("MSRS: Multi-Spectral Road Scenarios for Practical Infrared and Visible Image Fusion", Tang et al.) is obtained from the authors' repository `github.com/Linfeng-Tang/MSRS` at commit `5fa66e33c5ba`. The provenance record in `data/registry/MSRS.json` notes "Research use; cite the original paper". Images are **not** redistributed here, only the download script and the provenance record; check the upstream repository for its terms.

| split | pairs | use |
|---|---|---|
| `train/` minus holdout | 975 | fitting |
| holdout (10% of `train/`, sha1-ranked, seed 0, sha `fbf10e110601`) | 108 | monitoring, `best.pt`, all comparisons in this README |
| `test/` | 361 | evaluated once per run after training; informs no choice |

## Setup

Verified on Windows, Python 3.14.5, PyTorch 2.12.1+cu126, with an RTX 4070 Laptop GPU (8 GB) ([docs/ENVIRONMENT.md](docs/ENVIRONMENT.md)).

`requirements.txt` pins the exact versions used, including the CUDA 12.6 builds `torch==2.12.1+cu126` and `torchvision==0.27.1+cu126`. Those builds come from the PyTorch package index, not PyPI, so point pip at it:

```bash
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu126
```

On a machine without CUDA 12.6, install a matching torch/torchvision build first ([pytorch.org](https://pytorch.org/get-started/locally/)), then the remaining requirements. Only the versions listed were tested.

Then fetch the dataset:

```bash
python scripts/download_data.py --dataset msrs
python scripts/download_data.py --verify-only
```

`data/registry/MSRS.json` records where the dataset was downloaded on the original machine (`root`). On a fresh clone that path does not exist, so `--dataset msrs` downloads MSRS again and rewrites `root` in your local copy.

## Reproduce

Run the tests (the GPU tests need CUDA):

```bash
python -m pytest -q
```

Train and evaluate one model. This writes `experiments/<run_name>/` and ends with a single test-split evaluation and a benchmark. `run_experiment.py` itself does **not** guard against overwriting an existing run; the launcher below does:

```bash
python scripts/run_experiment.py --config configs/fusionedge.yaml
```

The configs for the three reported runs are `configs/baseline.yaml` (baseline v6), `configs/baseline_inject.yaml` and `configs/fusionedge.yaml`.

The full gated pipeline on Windows runs tests, pre-flight, the run, the audit and the acceptance gate. It stops at the first failure:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\win\protocol_run.ps1 -Run fusionedge_main -Cfg configs\fusionedge.yaml
```

Check finished runs and regenerate the comparison and documentation:

```bash
python scripts/audit_run.py experiments/fusionedge_main
python scripts/check_run.py experiments/fusionedge_main
python scripts/analyse_fusion.py experiments/baseline_simplecnn_inject experiments/fusionedge_main experiments/baseline_simplecnn_v6
python scripts/make_results.py --analysis results/analysis/<stamp printed by the previous command>
python scripts/make_showcase.py
python scripts/inventory.py
```

## Inference (demo)

Fuse one pair with the recommended model. `--run` loads that run's config and `checkpoints/last.pt`, the reported checkpoint, and `--fp32` matches the evaluation precision:

```bash
python scripts/infer.py --run experiments/baseline_simplecnn_inject --fp32 --ir data/MSRS/canonical/train/ir/00096D.png --vi data/MSRS/canonical/train/vi/00096D.png --out results/demo/baseline_inject_00096D.png
```

For FusionEdge or baseline v6, use `--run experiments/fusionedge_main` or `--run experiments/baseline_simplecnn_v6`. The command prints the output path and the mean |fused − visible|. On this pair, the demo output was verified to be pixel-identical to the evaluation forward pass for all three runs. Checkpoints are git-ignored, so a fresh clone must train first. The CLI **refuses** weights that look untrained, because an untrained model produces a plausible-looking but meaningless blend.

## Limitations

- **Few seeds.** The table above is seed 1234. The two inject-head models have three seeds each ([docs/RESULTS.md](docs/RESULTS.md)), which is enough for the pre-registered rule but gives weak spread estimates. Baseline v6 has one seed.
- **The inject head can only brighten.** Very hot objects lose visible texture (the truck wheels become near-white discs). At night it also adds IR sensor grain on road surfaces.
- **No ground truth.** No metric here measures "correctness". AG and SF use this project's definitions and are **not** comparable to published MSRS numbers.
- **Not compared with other methods.** No published fusion method was re-run under this protocol, so no claim is made against prior work.
- **Ablations not run.** The seven FusionEdge ablations (`configs/ablation_*.yaml`) have not been run.
- **Latency not broken down.** It was measured on one laptop GPU and not profiled per module.
